# Delhi/Kushak Rainfall-Runoff Engine Documentation

## Overview
This document describes the rainfall-to-runoff engine implemented for the SIH 2026 Urban Flood Nowcasting V2 scientific pipeline, specifically for the Delhi/Kushak V2 catchment (Provisional U2 = 27.66 km²). The engine transforms rainfall hyetographs into subcatchment hydrographs using physically interpretable water-balance logic, with strict exclusions as per project requirements.

## Methodology
The rainfall-runoff process consists of three main components:
1. **Loss Modeling**: Computes infiltration and depression storage losses using either Green-Ampt (physics-based) or SCS-CN (empirical) methods.
2. **Runoff Transformation**: Converts excess rainfall to hydrograph using a simplified Kinematic Wave approximation.
3. **Lateral Inflow Coupling**: Assigns subcatchment hydrographs to specific locations in the 1D hydraulic corridor.

All computations maintain rigorous unit tracking (mm, m², m³, m³/s) and verify mass balance conservation with error ≤0.10%.

## Exclusions
As per requirements, the following are explicitly excluded:
- SWMM or any hydraulic routing solver
- Channel flow solver (1D/2D)
- Flood depth/inundation mapping
- Machine learning or residual correction terms
- UI/backend API development

## Implementation Details

### Loss Models

#### Green-Ampt (Physics-Based)
Based on Darcy flow into wetting front:
- Infiltration capacity: \( f = K_s \left(1 + \frac{\psi \Delta \theta}{F}\right) \)
- Time-to-ponding calculated before Green-Ampt equation applies
- Depression storage tracked separately for impervious/pervious areas
- Parameters: hydraulic conductivity (Ks mm/hr), suction head (psi mm), moisture deficit (Δθ m³/m³)

#### SCS-CN (Empirical)
Standard NRCS NEH Part 630 approach:
- Potential maximum retention: \( S = \frac{25400}{CN} - 254 \) (mm)
- Initial abstraction: \( I_a = 0.2S \)
- Cumulative excess: \( P_e = \frac{(P - I_a)^2}{P - I_a + S} \) for \( P > I_a \)
- Composite CN calculated using EIA to partition built-up area:
  - \( f_{imp} = \text{built\_up} \times \text{EIA} \)
  - \( f_{perv} = \text{vegetated} + \text{built\_up} \times (1 - \text{EIA}) \)
  - \( f_{bare} = \text{bare\_soil\_rock} \)
  - \( CN_{composite} = f_{imp} \times CN_{imp} + f_{perv} \times CN_{perv} + f_{bare} \times CN_{bare} \)

### Runoff Transformation (Kinematic Wave)
Simplified approach appropriate for SIH V2 prototype:
1. Excess rainfall depth converted to volume: \( V = \frac{d_{excess}}{1000} \times A \)
2. Time lag applied based on overland flow travel time:
   - Overland velocity: \( v = \frac{1}{n} h^{2/3} \sqrt{S} \) (Manning's)
   - Time of concentration: \( t_c = \frac{L}{v} \)
3. Hydrograph generated by lagging excess rainfall volumes
4. Discharge approximated as finite difference of cumulative volume

### Lateral Inflow Coupling
- Default mapping: each subcatchment couples to a reach with matching ID as point source at chainage 0
- Supports user-provided reach mapping via `subcatchment_to_reach_mapping`
- Aggregates inflows by zone_id for hydraulic solver input

| Column | Units | Description |
|--------|-------|-------------|

#### Summary CSV (`summary.csv`)
| Column | Units | Description |
|--------|-------|-------------|
| subcatchment_id | - | Subcatchment identifier |
| total_precipitation_mm | mm | Total rainfall depth over event |
| total_loss_mm | mm | Total losses (infiltration + depression) |

| total_volume_m3 | m³ | Total runoff volume |
| mass_balance_error_percent | % | Mass balance error (should be ≤0.10%) |

## Mass Balance Verification
For each subcatchment, the engine verifies:
\[ P = L + E + \Delta S \]
where:
- \( P \) = total precipitation (mm)
- \( L \) = total losses (infiltration + depression) (mm)
- \( E \) = total excess runoff (mm)
- \( \Delta S \) = change in storage (assumed negligible for event-based)

Mass balance error is computed as:
\[ \text{Error} = \frac{|P - (L + E)|}{P} \times 100\% \]

A warning is printed if error exceeds 0.10%.

```bash
python -c "from backend.app.domain.delhi.hydrology.scenario_runner import main; main()"
```

This will process all combinations of:

- 5 subcatchments (SC-01 through SC-05)

## Notes on Prototype Approximations
Several simplifications are made for the SIH V2 prototype:
1. **Overland Flow Parameters**: Characteristic overland length estimated as √(area), slope assumed 0.01, Manning's n assumed 0.013
2. **Kinematic Wave**: Uses simple time-lag approach rather than solving PDE
3. **Lateral Coupling**: Default mapping assumes point sources at chainage 0; real applications should use spatially explicit mapping
4. **Depression Storage in SCS-CN**: Handled separately rather than via Ia to allow independent specification

These approximations are clearly marked in code comments and should be refined in future versions with spatially distributed parameter data.

## Validation
Outputs should be validated by:
1. Checking mass balance errors are ≤0.10%
2. Verifying runoff coefficients are physically plausible (0-1 range)
3. Ensuring peak discharges and times-to-pace are consistent with catchment characteristics
4. Comparing hydrograph shapes between loss methods for identical inputs
