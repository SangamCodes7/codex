# Quantitative Validation (Delhi/Kushak)

## What is validated

Machine-readable framework: `data/delhi/derived/science/observation_registry.*`,
`validation_metrics.csv`, `event_evaluation_matrix.csv` (regenerated by
`python scripts/run_scientific_evaluation.py`).

## Evidence gate (documented criteria)

Quantitative validation of a variable requires **Tier A/B observations of
that variable that are local to the Kushak corridor** AND a model quantity
comparable to them. The gate's actual verdicts:

| Variable | Supported | Why |
| --- | --- | --- |
| RAINFALL | YES (forcing QC only) | Tier A/B station records exist (102 interval rows + 6 event totals); computed metrics are forcing-input reproduction (**data-consistency QC, not hydrological skill**) |
| STAGE | NO | the only direct stage records are downstream Yamuna CWC bulletins — Tier A but spatially non-local (context only, per the CWC separation audit); no local Kushak stage observation exists |
| DISCHARGE | NO | no discharge observation exists anywhere in the evidence tree |
| FLOOD_EXTENT | NO | no surveyed inundation-extent observation exists |
| FLOOD_OCCURRENCE | NO | Tier C context only (categorical, mostly date-only) AND the runtime emits UNKNOWN reach states by contract (no stage) — there is no defensible predicted side, so precision/recall/F1 are NOT_COMPUTABLE; UNKNOWN is never converted to FLOOD_NO to fill a confusion matrix |

Every metric row carries: metric_name, event_ids, observation_type,
model_quantity, n_observations, temporal/spatial alignment, source_tier,
uncertainty, validity_status (COMPUTED / NOT_COMPUTABLE), and the reason.

## Computed metrics today

- Forcing reproduction MAE / RMSE / bias per executable event
  (EV-01/EV-02/EV-03), documented as forcing-pipeline QC.
- 23 explicit NOT_COMPUTABLE rows (stage/discharge/extent/occurrence
  families) with per-family reasons — never hidden, never invented.

## Event separation

No event is consumed by training or calibration (none performed). The
three executable events stay an unsplit evaluation pool; the control
event stays reserved; missing-forcing events stay non-executable. Any
future calibration MUST draw CALIBRATION_EVENTS from the pool and hold
out at least one event calibration never sees (audit-enforced).
